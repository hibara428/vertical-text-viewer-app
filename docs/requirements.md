# 要件 (draft v0.5)

## 概略

- 青空文庫の作品を読める、日本語ビューアーサイト
- 目的は次の2つ
  1. 縦書き/横書き・スクロール/ページめくりなど、複数のビューア実装を作って試すこと自体
  2. それらを通じて、最終的に使いやすいビューアへ収束させること
- CMS機能は不要。コンテンツは青空文庫のテキストデータ
- 個人の自作小説を公開する話は本サイトのスコープ外(将来、別リポジトリ/別サイトで改めて検討)

## スコープ

- **プロトタイプ**: 少数のテキストを手元でリポジトリに同梱し、ビューア実装を試すだけの検証段階。外部データ取得は行わず、リリース対象には含めない
- **初回リリースのスコープ**: 青空文庫の**著作権切れ作品全体**を閲覧できること。具体的には次を含む
  - 任意の対象作品を実データで取得・パースして表示できる
  - 作品を探す導線を2つ用意する
    - 五十音による作者ブラウジング
    - 作品名・著者名での検索(読み仮名でも引けること)
  - 取得結果がキャッシュされ、外部サービスへの負荷が抑えられている
- **将来検討**: 初回リリースがある程度形になってから改めて要件・設計を立てる
  - 本文の全文検索は対象外(上記の検索は作品名・著者名のみ)
- 実装をどの順番で進めるかは [docs/design.md](./design.md) のロードマップを参照

## コンテンツに関する制約(青空文庫由来)

- 扱う作品は**著作権切れのものに限定する**(著作権存続中の作品を再配布するには権利者の許可が必要なため)
- 青空文庫のテキスト末尾にある**底本情報**(底本名・入力者・校正者など)は、本文から分離して別途表示する(青空文庫の慣習としてクレジットの保持が期待されている)

## コンテンツモデル

- **作品 (Work)**: タイトル・作者などのメタ情報を持つ。青空文庫の1エントリ = 1作品
  - 階層(章)は持たない。青空文庫の実データには「1作品が複数の章に分かれる」という親子構造がなく、長編の分冊(上巻・下巻など)も独立した別エントリとして登録されているため(例: 大菩薩峠の各巻は別カードID)
  - 複数巻をまとめて「シリーズ」として見せる機能は、必要になれば別途独立した機能として検討する
- **作者 (Author)**: 作品は必ず1人の作者に属する。青空文庫の実データも作者(人物ID)の下に作品がぶら下がる構造になっており、これに対応する
- **フォーマット**: 本文は**青空文庫フォーマット**(ルビ・傍点・注記などの記法)のみを対象とする。自作小説など他フォーマットへの対応は現時点でスコープ外

## ビューア

本サイトの中心テーマ。複数の読み方モードを実装し、比較・改善していく。

- 読み方モード(初期案。実装しながら増減しうる)
  1. 横書き・縦スクロール
  2. 縦書き・縦スクロール
  3. 縦書き・横ページめくり
- ルビ・傍点など青空文庫記法の表示に対応
- モバイル操作を重視する(横スワイプに頼らない読み方も用意する)
- 上記以外のビューアUIの仕様は [docs/viewer-design.md](./viewer-design.md) で詰める

## 非機能

- 低コスト
- 省運用
- レスポンシブ対応
